MsgDock is an open-source, provider-aware communication sandbox for local development and CI. Capture email and SMS locally, inspect the messages, and keep real users and external providers out of the loop.

01 / QUICK START

Point your app at MsgDock.

There is no MsgDock-specific SDK required for basic capture. Change your local transport configuration and keep your application code intact.

Install + run
npm install
npm run dev

Requires Node.js 20+ and npm. The development command starts the Web UI and Core runtime together.

Nodemailer
const transporter = nodemailer.createTransport({
  host: 'localhost',
  port: 1430,
  auth: { user: 'msgdock', pass: 'msgdock' },
});

Captured email is stored locally. MsgDock does not deliver captured mail externally.

i

Local data is stored in .msgdock/msgdock.sqlite by default. SMS capture is opt-in: MSGDOCK_SMS_ENABLED=true npm run dev.

02 / ARCHITECTURE

Small boundaries.
Clear responsibilities.

MsgDock keeps protocol adapters, domain logic, persistence, API transport, and the UI separate so the local runtime can grow without turning into a distributed system.

Lifecycle events stay inside the runtime today. Future consumers can attach without coupling the core to queues or external infrastructure.

Protocol packages use core abstractions; SQLite implements the repository boundary; the UI talks through the typed API client.

04 / FAQ

Things worth knowing.

Does MsgDock send messages to real users?

No. The current runtime is designed for local capture. SMTP messages are parsed, normalized, and stored locally rather than delivered to an external provider.

Do I need to change application code?

For email capture, no MsgDock SDK is required. An existing SMTP-based application can point its SMTP transport at localhost:1430.

Where are captured messages stored?

SQLite is used by default, with the database at .msgdock/msgdock.sqlite.

Is SMS supported?

Local SMS capture is currently available through the HTTP ingestion endpoint on localhost:1431 when MSGDOCK_SMS_ENABLED=true. External SMS provider integrations are future work.

What is planned next?

The project is structured to support additional channels, providers, lifecycle simulation, callbacks/webhooks, and other future capabilities. Those are not presented as current functionality.
